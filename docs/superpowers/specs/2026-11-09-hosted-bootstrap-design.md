# Hosted bootstrap

Implement a separate environment-only operator CLI for hosted Supabase. Keep the three local entry points and their guards unchanged. Before opening clients, validate the project reference, matching Auth host and database username, non-local hosted targets, required credentials and test-only Stripe key. Build pg options from parsed fields with the committed CA and certificate verification; URL query parameters cannot replace TLS options.

Writes require `--apply`; previews may read hosted state and Stripe prices but never invite or mutate. Content validates the committed pending-review catalog with the sole clinician ID and calls the existing publisher. Settings and waitlist call their existing validators/publishers. Status projects only versions, price IDs and counts, never content or addresses. Failures report only a fixed generic message and a controlled code.

Clinician invitation must first enable the normalized email in the allowlist because the current Auth trigger requires it and creates a profile plus launch case. Use the Admin invitation endpoint with the supplied HTTPS portal `/reset-password` redirect. Reuse an existing Auth identity on reruns, then ensure the fixture-compatible dermatologist row (`id`, display name, email, `UNUSED_SUPABASE_AUTH`) and profile without resetting existing profile fields. Refuse a different or multiple launch clinician; serialize clinician runs with a session advisory lock over the session pooler on port 5432 (reject transaction pooling). Invitation is outside the SQL transaction: after a partial failure, rerunning repairs the rows without resending the invitation. Do not delete existing identities or trigger-created rows.

Acceptance: pure guard tests and injected fakes for every command, default dry-run, invitation/retry/conflict cases, exact fixture shape, Stripe validation, sanitized status/failures and verified CA options. Extract the existing revision schema into a pure module so shared content validation never constructs Prisma or reads dotenv; preserve its service re-exports. Catch asynchronous pg error events and sanitize the Admin transport before SDK logging can run. No hosted execution. Run `cd backend && npm test && npm run build`, perform access review, commit on the supplied feature branch with the requested coauthor trailer.
