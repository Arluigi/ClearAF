## Where to pick up

1. **TestFlight is blocked on Apple, not on code.** The reviewing clinician must accept the Program License Agreement as Account Holder (App Store Connect refused to create an API key without it), confirm the Free Apps agreement is Active, then generate a team API key with App Manager access. With the `.p8`, Key ID and Issuer ID in `~/.appstoreconnect/private_keys/`, the remaining work is one pass: register the bundle ID in his team, create the app record, archive and upload a Release build, answer export compliance, add him as an internal tester. Internal testers need no Apple review.
2. **The phone is a build behind.** `com.clearaf.patient` with the quick-replies release is not installed; the device carries the previous Release build under the old identifier.
3. **Production holds synthetic accounts.** A `clearaf-demo-…@example.invalid` clinician exists there, created ad hoc rather than by a committed fixture. Before a real reviewer signs in, audit what synthetic patients and photos production is carrying.
4. **The retention and deletion policy is still unapproved**, and it gates external TestFlight and the App Store: Apple requires in-app account deletion for any app with accounts, and this app deliberately shows an unsupported-removal status instead. A clinical decision, not a coding one.
5. **Unverified on hardware:** photo Compare with two real photos, and the dark and tinted app icons. Both failed to verify on this Mac for environment reasons, not product ones (below).

## Machine notes that cost time

- **Run one `xcodebuild` at a time, in the foreground.** Concurrent Simulator test runs deadlocked for seven hours overnight at 0% CPU. Kill with `pkill -f xcodebuild; xcrun simctl shutdown all`.
- **The `axe`/xcodebuildmcp tap channel is broken** on Xcode 27 with macOS 26.6: simulated taps deliver nothing. Use XCUITest through `xcodebuild` instead.
- **The Simulator's photo picker hangs**, and photos sync device→server only, so a server fixture cannot seed a device. Photo-dependent screens need a real phone.
- **The Simulator home screen will not swap app-icon appearances.** Verify icon variants with `assetutil` on the compiled `Assets.car`, or on a device.
- **`vercel --prod` failed with "Not authorized"** until `--scope arluigis-projects` was passed explicitly. The CLI is several versions behind.
- **`vercel env pull` cannot retrieve Secret-marked values**; it writes `[SENSITIVE]` placeholders. Operational scripts need credentials supplied another way.

## Standing constraints

Unchanged and worth re-reading before the next feature: the access model (clients never touch tables or Storage), two clients one contract, no schema changes without `/new-migration`, and the Letterpress copy rules in [`design-language.md`](../design/design-language.md) — including the one documented exception, that clinician quick replies may carry brief encouragement after a factual clause and never assess the skin.
